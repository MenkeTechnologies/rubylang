# Triaged parity-fuzz gaps.
#
#   ./target/debug/parity-fuzz --mode all --baseline tests/data/parity_fuzz_baseline.txt
#
# Each line is a gap SIGNATURE (the divergent program with its literals replaced
# by `N`/`W` placeholders, so every instance of one bug collapses to one line).
# A divergence whose signature is listed is reported as "known" and does not fail
# the run; anything else is NEW and exits 1.
#
# This file is an admission of a gap, never a fix for one. A line belongs here
# only when the divergence has been traced to a cause that is understood and
# recorded below — not because a run was noisy. Delete the line when the cause is
# fixed; a stale line silences a bug that has come back.
#
# ---------------------------------------------------------------------------
#
# A byte string whose bytes are not valid UTF-8 loses them on the way back to a
# UTF-8 label, and a `"\xNN"` literal never had them in the first place:
#
#   $ /opt/homebrew/opt/ruby/bin/ruby -e 'p [11, 169].pack("C*").force_encoding("UTF-8")'
#   "\v\xA9"
#   $ ./target/debug/ruby            -e 'p [11, 169].pack("C*").force_encoding("UTF-8")'
#   "\v�"
#
#   $ /opt/homebrew/opt/ruby/bin/ruby -e 'p ["\xff".bytes, "\xff".valid_encoding?]'
#   [[255], false]
#   $ ./target/debug/ruby            -e 'p ["\xff".bytes, "\xff".valid_encoding?]'
#   [[195, 191], true]
#
# Cause: `RObj::Str` is a Rust `String`, so it cannot hold invalid UTF-8 at all.
# The byte-string representation invariant (see `builtins.rs`) buys back every
# byte string that stays LABELLED as one — its storage is one character per byte,
# so `#bytes`, `#bytesize`, `#length`, `#[]`, `#inspect` and the `pack`/`unpack`
# round trip all answer MRI's byte-oriented result. What it cannot buy back is a
# string that MRI labels UTF-8 while holding bytes that are not UTF-8: there is
# no representation for it here, and the conversion is lossy.
#
# This is the whole of the residual gap, and it is bounded by that description.
# Closing it needs `RObj::Str` to become a byte buffer with a separate encoding
# field — MRI's own representation — which is a change to the object model, not
# to any String method.
p [N, N].pack(W).force_encoding(W)
#
# ---------------------------------------------------------------------------
#
# The rendering of a non-String object is UTF-8 here and US-ASCII in MRI:
#
#   $ /opt/homebrew/opt/ruby/bin/ruby -e 'p nil.to_s.encoding.to_s'
#   "US-ASCII"
#   $ ./target/debug/ruby            -e 'p nil.to_s.encoding.to_s'
#   "UTF-8"
#
# Cause: DELIBERATE, on cost. MRI gives US-ASCII to every interpreter-produced
# string with 7-bit content — `nil.to_s`, `1.to_s`, `:ab.to_s`, `[1, 2].to_s`,
# `1.inspect`, `(1..2).to_s`. Recording that here means one hash insert per
# `to_s`, which measured ~8% on a `to_s`-only loop (300k iterations, user CPU,
# interleaved runs against the unmodified binary: 6.42/6.48/6.74s before,
# 6.94/7.08/7.29s after).
#
# What it buys does not pay for that. The tag is observable ONLY through
# `#encoding`: `#inspect` picks the byte escape form over the codepoint form for
# a non-UTF-8 string, but the two forms are identical on the 7-bit content this
# rule applies to, so nothing a program PRINTS changes either way. `to_s` is the
# hottest conversion in the language and this is a rarely-asked question about
# its result.
#
# The same tagging on a String receiver IS kept (`"a".b.to_s.encoding` is
# ASCII-8BIT) — that path is already inside the encoding-aware branch and costs
# nothing extra.
# The second signature is the same gap reached through an out-of-range index:
# `"a b".b[9]` is nil, so this is `nil.to_s.encoding` with a byte string only
# incidentally in the expression.
p nil.to_s.encoding.to_s
p W.b[N].to_s.encoding.to_s
